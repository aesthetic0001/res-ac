# Woozoo PCF-SC15T-CT infrared control

The Seeeduino Cloud AVR sends **38 kHz extended NEC** on **digital pin 9**.
The DHT11 remains on digital pin 3. Arduino-IRremote is pinned to 4.4.1 and uses
a software carrier at 50% duty; no receive timer or IR input is enabled.
Nothing transmits automatically at startup.

## Calibration and estimated state

Every AVR restart starts **uncalibrated**. Before any IR command can run, restart
the fan to **factory position: off**: unplug it, plug it back in, and leave it
off. In the dashboard, check **I restarted the fan and left it off**, then choose
**Confirm off and enable remote**. Enqueuing that confirmation alone does not
unlock the controls: the AVR must accept it and report a calibrated state.

The AVR owns the estimate in RAM. Calibration sets estimated power to off and
assumes the next power-on uses speed 1 of 5. Power toggles preserve the remembered
speed, and speed presses wrap cyclically through levels 1–5 while on. These are modeling
assumptions to verify on the actual fan, not measured settings. A missed IR press,
the physical remote, or the fan's buttons can make the estimate inaccurate.
Use **Calibrate fan** again after changing the fan externally.

An AVR restart, Linux agent restart, missing agent heartbeat for 10 seconds,
interrupted IR acknowledgment, or unmodeled command invalidates calibration.
Timers, breeze, unknown codes and repeated NEC frames are transmitted only when
already calibrated, then invalidate the estimate because their effects are not
modeled. Horizontal/vertical oscillation preserves the power/speed estimate.

Calibration is bound to a random session generated by the Linux agent after
the AVR requests a new session. Queued confirmations and IR commands from an old
session are rejected by the AVR. USB serial IR and generic API commands obey
the same calibration gate. No EEPROM calibration survives a restart.

Live state is posted independently of buffered sensor readings to
`POST /api/devices/<id>/fan-state`. The dashboard displays **Estimated: Off** or
**Estimated: On · Speed N / 5**. Missing or older-than-30-second state disables
controls and calibration confirmation. The API also requires fresh telemetry,
the matching session, and calibration before accepting IR commands.

## Emitter wiring

The ordered [Gikfun kit](https://www.amazon.ca/dp/B06XYNDRGF) contains loose
940 nm emitting diodes and VS1838B receivers, rather than a complete GPIO
transmitter module. Use an **emitting diode**, observing its polarity. The
receivers are for capturing a remote's signal and are not used by this sending
firmware. Confirm component identity with the supplied specifications rather
than relying only on package color.

For an initial short-range test, with the board disconnected from power:

```text
Seeeduino D9 ---- 470 ohm resistor ---- IR LED anode (+)
Seeeduino GND ------------------------ IR LED cathode (-)
```

An untrimmed LED normally has the longer lead at its anode and a flat package
edge at its cathode; verify the actual part. The resistor is required. On this
5 V board, 470 ohms limits current to less than 11 mA even before allowing for
the LED voltage drop. Aim the LED directly at the fan's IR window and begin
close to it. Infrared is invisible; some phone cameras also filter it out.

For a transistor driver, connect D9 through 1 kohm to an NPN base, add 10 kohm
from base to ground, connect emitter to ground and collector to the IR LED
cathode. Connect +5 V through the LED series resistor to its anode. Verify the
transistor pinout. Start with 470 ohms here too; choose a lower series resistance
only from the emitter's verified current/voltage ratings and driver limits.
The kit listing alone is not a verified high-current pulse specification.

The [Seeed board documentation](https://wiki.seeedstudio.com/Seeeduino_Cloud/)
identifies the AVR as a 5 V ATmega32u4 compatible with Arduino Yun.

## Starting button profile

The [SC15T capture and protocol explanation](https://randomblock1.com/blog/smartifying-dumb-fan)
provides address **`0xDE80`** and the commands below. These are captured on the
blog's fan, **not yet verified on PCF-SC15T-CT**. The supplied remote photographs
show different button positions; position alone does not establish a code.
We initially reuse the captured functions, rather than renumbering by position.

| `fan.command` button | NEC command |
| --- | --- |
| `power` | `0x00` |
| `speed_up` | `0x08` |
| `speed_down` | `0x10` |
| `breeze` | `0x09` |
| `horizontal` | `0x15` |
| `vertical` | `0x16` |
| `timer_1h` | `0x12` |
| `timer_2h` | `0x0E` |
| `timer_4h` | `0x0A` |

Power and oscillation are remote button presses with toggle behavior, not
absolute on/off settings. Power and speed are estimates after calibration.
The CT remote's timer-cycle, combined oscillation, light and
mute buttons have no verified mapping here. The blog's unexplained `0x02`
behavior has no named button. Avoid sweeping unknown codes.

[Modern IRremote](https://github.com/Arduino-IRremote/Arduino-IRremote/tree/v4.4.1)
accepts a 16-bit address and an 8-bit command, sends LSB first, and generates
the command complement. Use `0x08`, not ESPHome's `0xF708`, for speed up.
In transmission order the four speed-up bytes are `80 DE 08 F7`.

## Target levels and temperature curves

The remote's **Set level** controls request an absolute estimated target, 1–5,
or 0 for off. The AVR computes `forward = (target - current + 5) % 5` and
`backward = (current - target + 5) % 5`, then sends the shorter sequence of
individual NEC button presses. There are at most two speed presses. For example,
3 → 4 uses one up press, 1 → 5 uses one down press, and 5 → 2 uses two up presses.
Power is separate: an off fan is powered on first, using its remembered speed;
requesting off sends a power toggle only if the estimate says on. Requesting the
current level sends no IR. Individual presses are separated by 150 ms; NEC
short-repeat frames are not used to move multiple levels.

**Automatic temperature curve** offers these editable starting presets. Each
temperature is the threshold for levels 1, 2, 3, 4, and 5 respectively; below
the first threshold the target is off:

| Preset | Thresholds (°C) |
| --- | --- |
| Quiet | 24, 26, 28, 30, 32 |
| Balanced | 22, 24, 26, 28, 30 |
| Cooling | 20, 22, 24, 26, 28 |

Edit the graph by dragging each level handle horizontally, or focus a handle
and use Left/Right (0.5 °C), Shift+Left/Right (5 °C), or Home/End. Neighboring
handles follow when necessary to keep thresholds nondecreasing. Number fields
stay synchronized and also accept precise fractional temperatures. Graph edits
remain unsaved until **Apply curve** is pressed.

Equal thresholds are allowed and select the highest matching level. For example,
`[22,24,24,24,30]` selects level 4 at 24 °C, while `[24,24,24,24,24]` jumps directly
from off to level 5 at 24 °C. The solid line connects the control points; the
dashed step curve shows the applied discrete levels. Cooling hysteresis still
applies, including dropping an equal-threshold group together.

The Seeeduino's Linux agent evaluates fresh DHT11 samples locally, so operation
does not depend on a backend temperature polling job. On heating, a threshold
applies as soon as it is reached. On cooling, its configurable hysteresis (default
1 °C) must also be crossed: with the balanced preset, level 3 begins at 26 °C
and steps down at or below 25 °C. Automatic adjustments are at least 30 seconds
apart. Sensor reads occur at least every 10 seconds while automatic mode is
enabled, even if the normal reporting interval is longer.

Settings are atomically persisted in `/etc/res-ac/fan-curve.json` (mode 600).
Automatic mode is off by default. Saved enabled settings survive agent/device
restarts, but cannot send IR until calibration and a fresh post-startup sensor
sample are available. Read errors or samples older than 30 seconds pause
adjustments. A command execution failure stops automatic mode. Manual target,
power, or speed commands switch automatic mode off; USB serial IR changes are
detected through the AVR's control-source/revision report and also stop it.
Manual and automatic commands share one mailbox and never execute concurrently.
Automatic physical-command journals are RAM-backed, avoiding recurring flash
writes for temperature-driven adjustments. Restart always invalidates calibration.

The API command `fan.level` accepts `{"level":4,"sessionId":"CURRENT_SESSION"}`.
`fan.curve` accepts `{"enabled":true,"thresholdsC":[22,24,26,28,30],"hysteresisC":1,"sessionId":"CURRENT_SESSION"}`.
Both require firmware `v4` and a fresh matching session. Enabling a curve and
setting a level require calibration; saving a disabled curve is allowed before
calibration. `fan.curve` success means the Linux agent saved the settings, while
`fan.level` success requires a matching AVR acknowledgment including the number
of IR presses. Automatic status and desired level are included in live fan state.

The new level frames are `v4,<UUID>,level,<session>,<0..5>` and
`v4,<UUID>,auto_level,<session>,<0..5>`. The response is
`v4,<UUID>,level_set,<session>,<level>,<presses>,<uptime-ms>`. Calibration and raw
NEC retain their `v3` frame format. The `v4` sketch publishes
`v2,<session>,<calibrated>,<power>,<speed>,<revision>,<control-source>` with source
`reset`, `calibration`, `manual`, or `automatic`.

## Build, install and test

Build and flash the AVR from the project root:

```sh
~/.platformio/penv/bin/pio run
~/.platformio/penv/bin/pio run -t upload
~/.platformio/penv/bin/pio device monitor
```

The USB monitor runs at 115200 baud. Wait for `Bridge ready` and the new agent
to establish its heartbeat/session. Restart the fan and leave it off, then
confirm that baseline and test with these lines, each followed by LF (Enter):

```text
calibrate off
ir 0xDE80 0x00
ir 0xDE80 0x08
```

This transmits one speed-up press. `ir 0xDE80 0x10` decreases speed and
`ir 0xDE80 0x00` toggles power. The updated Linux agent and Bridge service must
be running, including for local serial calibration and IR tests.
If the fan does not react, check diode identity/polarity, wiring, alignment and
range before assuming the codes match. Capture the original CT remote with a
38 kHz demodulating receiver if the profile proves incompatible.

For dashboard control, upgrade **both** the Linux agent and AVR sketch using
the existing [installation procedure](README.md#configure-and-install). On an
already configured board, close the monitor, upload the recovery project,
run the installer with the existing private configuration, then flash the main
project. The recovery sketch is needed only for installing the Linux agent.
This source change does not itself flash or update a connected board.

The remote handles calibration and session IDs automatically. In the generic
command form, first submit type `fan.calibrate` with the device's current
`fanState.sessionId` from `/api/admin/state` and an explicit confirmation:

```json
{"confirmOff":true,"sessionId":"CURRENT_32_CHARACTER_SESSION_ID"}
```

After the AVR reports calibration, submit type `fan.command` and payload:

```json
{"button":"speed_up","sessionId":"CURRENT_32_CHARACTER_SESSION_ID"}
```

Other names are in the table above. For captured replacement codes, use type
`ir.send` with numeric JSON fields (JSON does not support hexadecimal literals):

```json
{"protocol":"NEC","address":56960,"command":8,"repeats":0,"sessionId":"CURRENT_32_CHARACTER_SESSION_ID"}
```

Address must be 0–65535, command 0–255, and optional repeats 0–3. Named buttons
always use zero repeats. Repeats send NEC short repeat frames; they are not an
absolute speed setting. Use separate presses when testing relative speed.

## Delivery behavior

The backend supplies a UUID and UTC expiry. The agent checks expiry and clock
validity before dispatch, persists an uncertain result, then writes one atomic
Bridge request: `v3,<UUID>,nec,<session>,<address>,<command>,<repeats>` (decimal numbers).
The AVR acknowledges **after sending** with
`v3,<UUID>,ir_sent,<session>,<address>,<command>,<repeats>,<uptime-ms>`.
Success requires the matching UUID and all transmitted parameters. It means
the waveform was sent; `fanStateConfirmed` is always `false`.
Calibration uses `v3,<UUID>,calibrate,<session>` and is acknowledged with
`v3,<UUID>,calibrated,<session>`. Rejected session/calibration gates return
`v3,<UUID>,rejected,<session>` without sending IR.

The AVR caches its most recent reply so rereading a mailbox does not resend IR.
The agent journals the final result and retries HTTPS acknowledgment without
transmitting again. An interrupted IR action reports uncertainty on restart;
it is not automatically replayed. The agent sends the mailbox only once, and
the AVR clears stale requests on startup, so an AVR reset also does not trigger
an automatic resend. A lost Bridge write can therefore fail without a send.
Missing responses time out after 10 seconds. Inspect the fan before issuing a
new command after an uncertain result. This favors avoiding duplicate toggles;
it does not provide exactly-once physical delivery or state feedback.
